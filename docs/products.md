# 维护产品目录

所有产品写在 `data/products.json`。数组顺序就是完整目录与作品星图的顺序。首页已取消“正在重点做”精选区，全部作品直接进入完整目录与星图；保留的 `featured` 字段不再影响页面展示。

星图使用原生 WebGL 绘制带光照的产品球体和空间轨道，使用同一条产品数据的图片、名称、描述和链接。每组最多显示 6 件，更多作品可以切换分组；完整目录始终默认显示全部。可拖动旋转或使用方向按钮，支持暂停。减少动态效果时保持静止；没有 JavaScript、WebGL 不可用或图形上下文丢失时，显示静态作品链接。

## 最小条目

以下只是格式示例，不是实际成果。发布前替换名称、描述和链接。

```json
{
  "id": "my-next-product",
  "name": "新产品名称",
  "description": "用一句话说明它帮谁解决什么问题。",
  "category": "实验项目",
  "status": "原型展示",
  "href": "https://example.com/",
  "action": "体验原型"
}
```

`id` 使用稳定、唯一的小写英文与连字符，不使用页面已有锚点（如 `top`、`projects`、`about`、`contact`）。分类直接使用可读名称，例如阅读工具、互动叙事、生活工具、网页产品、实验项目；筛选项和数量根据数据生成，没有作品的分类不显示。

## 图片与说明

- `image`：项目内真实截图路径，例如 `assets/products/example.png`。
- `imageAlt`、`imageWidth`、`imageHeight`：准确的图片描述及实际尺寸。
- `featured`：旧版兼容字段，不再生成精选区。不要用概念图代替产品实机画面。
- `subtitle`：可选的英文名或补充定位。
- `notes`：可选的 `title`、`text` 对象数组，生成可展开的创作笔记。
- `notice`：可选的使用说明；`source`：可选的公开源码链接。
- 没有图片的普通作品会以名字首字显示，也可用 `mark` 指定文字标记。

没有公开入口时，使用 `href: "#作品id-notes"` 和 `action: "了解作品"`，同时提供 `notes`，状态写“作品展示”。不要添加不可用的安装或试玩按钮。小账本是现有例子。

## 更新与发布

1. 修改产品数据；若新增截图，将它放入 `assets/products/`。
2. 运行 `npm run build`。它生成根目录静态首页、检查本地链接和数据，再输出 `dist/`。
3. 提交数据、截图以及生成后的 `index.html`。仓库保留静态首页，以兼容直接访问文件和现有分支发布路径。
4. GitHub Pages 工作流再次从数据构建并发布。确认部署完成后检查公开站点。

`npm run check` 检查生成的首页是否与数据同步；`npm test` 用内存中的模拟产品检查新增分类、精选数量上限、转义与原有锚点，不会把测试数据写入生产文件。

全部作品默认完整展示，包含精选产品，因此筛选结果和总数始终一致。直接访问旧作品锚点会显示对应作品；即使之前筛选隐藏了该项，也会恢复完整目录。全部内容在 HTML 中预先生成，脚本只增强筛选、主题和轻动效。
